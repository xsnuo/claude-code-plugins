# key-points：标重点

[English](README.md) | 简体中文 · [← 返回插件列表](../../README.zh-CN.md)

每条 Claude 最终回复的末尾有一个「📌 key points」。点一下，Claude 会结合整段对话，从这条回复里挑出**关注句**和**关注词**，直接在原回复上标出来；再点一下就取消。

不会生成新的回复，存下来的原文一个字也不改，改的只是这条回复显示出来的样子。

## 安装

```
/plugin marketplace add xsnuo/claude-code-plugins
/plugin install key-points@xuesinuo
```

## 用法

- **标重点**：点「📌 key points」。等待时显示「⏳ key points…」，一般几秒钟，标好后链接变成「📌 hide key points」。
- **取消**：再点一次，回复恢复原样。之后再点会直接显示刚才的结果，不会再问一次 Claude。
- **出错了**：链接会写明原因，比如「⚠️ key points: API 529, retry」，点它重试。
- **和 aload 一起用**：两个插件都装了时，「🔊 read aload」和「📌 key points」并排在同一行；只装一个时，那一行里就只有它自己。

### 什么算重点

插件会请 Claude 按下面几条来挑：

1. 这段对话探讨的核心；
2. 直接、简练地回答你提问的部分；
3. 需要你知晓、或需要你做决策的内容；
4. 其他 Claude 认为重要的内容。

挑出来的重点分两类：关注句是一句或半句话，关注词是关键的词或短语，关注词可以落在关注句里面。

**重点不超过正文的 25%。** 这条由插件计算并强制执行，不靠 Claude 自觉：
- 按 Claude 给出的重要性顺序逐个加，加上某一处会超过 25% 就跳过它；
- 关注词在文中出现几次就标几次，每一处都算进篇幅；
- 词和句重叠的部分只算一次；
- 代码块不算篇幅。

### 后台提问不会出现在对话里

点链接时，插件会在后台另发一次请求：把这段对话的上下文原样带上，再加上这条回复和上面的要求。
- 这次问答不进对话记录，也不在界面上显示。
- 少数情况下没法带上上下文，比如刚恢复的会话还没聊过，这时只带这条回复去问。

## 标注方式

默认：关注句用黄色字（主题里的 `warning` 色，深色、浅色主题下都看得清）；关注词用荧光黄背景、黑色字。

字体色、背景色、下划线三样可以自由组合，关注句和关注词分开设置：

| 命令 | 作用 |
|---|---|
| `/key-points` | 查看当前的标注方式 |
| `/key-points sentence color <颜色>` | 关注句的字体色；`none` 表示不改字色 |
| `/key-points word bg <颜色>` | 关注词的背景色；`none` 表示不加背景 |
| `/key-points sentence underline on` | 关注句加下划线；`off` 去掉 |
| `/key-points reset` | 恢复默认 |

- `sentence` 也可以写成 `句`，`word` 也可以写成 `词`。
- 颜色有四种写法：
  - `#RRGGBB` 或 `#RGB`；
  - 颜色名，如 `yellow`、`redBright`；
  - 主题色，如 `warning`、`success`；
  - 中文单字，如 `黄`、`红`。
- 设置会保存下来，下次会话照样生效。
- 下划线的颜色跟着字色走，没法单独设置线的颜色。

## 运行要求

- **Claude Code 2.1.299 或更高版本**（在这个版本上开发和测试），并开着全屏模式（`/tui fullscreen`），这样才能用鼠标点链接。
- **终端要支持超链接**，Ghostty、iTerm2 等都可以。链接在不支持超链接的终端里点不了。
- 插件只有 TypeScript 代码，不需要 Python，也不调用系统命令。不过目前只在 macOS 上测过。

## 费用

每点一次「key points」，就多发一次请求，按你当前的模型计费：
- **输入**：
  - 前面的上下文和主对话共用缓存，按缓存读取计费，大约是正常输入价的 1/10；
  - 隔了很久（缓存过期）再点，整段上下文要按原价重新计费。
- **输出**：只有几十到几百个 token。

取消后再显示，用的是留着的结果，不会再花钱。

## 已知限制

- **带重点的段落由插件自己画。** 引擎画回复用的 Markdown 组件，没法只给其中一部分文字上色，所以含重点的段落由插件逐行画。粗体、斜体、行内代码、链接、列表都照着画，但和引擎画的样子可能有细微差别。不含重点的段落仍然交给引擎画。
- **代码块和表格里的内容不标。**
- **aload 用每段一个按钮的模式（`/aload icon paragraph` 或 `hover`）时，两者会互相遮挡：**
  - 标着重点时，那条回复可能只有第一段显示标注；
  - 或者 aload 每段的 🔊 暂时不显示。
  - aload 默认的「每条回复末尾一个」模式没有这个问题。

## 开发

- **测试**：在本目录下运行 `claude plugin test .`。
- **文件**：

| 文件 | 作用 |
|---|---|
| `hooks/register.tsx` | 插件本体：回复末尾的链接、后台提问、`/key-points` 命令 |
| `hooks/marks.ts` | 纯逻辑：问 Claude 的话、读回答、在原文里找重点、25% 上限、行内 Markdown 解析 |
| `hooks/draw.tsx` | 把带重点的回复画出来 |
| `hooks/blocks.ts` | 把回复切成段（和 aload 的切法一致） |
| `hooks/actions.tsx` | 回复下面的「操作行」，和 aload 共用；两个插件各带一份，改的时候两边一起改 |
| `types/index.d.ts` | 插件状态的类型 |
| `tests/` | 插件测试，用模拟的引擎和模型，不联网 |
